# Goblin Studios • Website

Official website for Goblin Studios, an indie/double-A game development studio specialized in Unreal Engine, based in São Paulo with global operations. Originally scaffolded via Lovable, fully decoupled and rebuilt into an independent, self-hosted React stack.

**Live at:** [https://www.goblinstudios.com.br](https://www.goblinstudios.com.br)

## Getting Started

### Requirements

- [Bun](https://bun.sh/) v1.0 or higher
- Node.js is **not** required for the frontend -- Bun handles everything
- [Vercel CLI](https://vercel.com/docs/cli) (`bun add -d vercel`) -- required only to run the serverless API functions locally

### Install dependencies

```bash
bun install
```

### Run frontend only (no API functions)

```bash
bun run dev
```

Opens at `http://localhost:8080`. Use this for UI/content work. Any `fetch()` call to the API functions will hit production directly (see **API Functions** below), since both `contact.ts` and `playtest-signup.ts` are called via their absolute Vercel URL, not a relative path.

### Run with local API functions

```bash
bunx vercel dev
```

Opens at `http://localhost:3000`. Required to test `api/contact.ts` or `api/playtest-signup.ts` changes before deploying. Requires a local `.env` or `.env.local` with the API keys below -- see **Environment Variables**.

### Build for production

```bash
bun run build
```

Output goes to `dist/`.

### Preview production build

```bash
bun run preview
```

Always run this before deploying -- `bun run dev` does not surface production-only bugs like chunk-splitting issues (e.g. i18n library duplication across Rollup chunks).

## API Functions

The frontend is a static SPA hosted on Hostgator, but two serverless functions run separately on Vercel. Because they live on a different domain (`https://goblins-site.vercel.app`) than the public site (`https://www.goblinstudios.com.br`), both are called using their **absolute URL**, and both implement manual CORS restricted to the production domain and `localhost:8080`.

### `api/contact.ts`

Handles the project inquiry form on `/contact`.

- Validates a Cloudflare Turnstile token server-side before proceeding
- Renders an HTML email via `@react-email/components` and sends it through Resend
- Destination: `contact@goblinstudios.com.br`
- Uses `RESEND_API_KEY`, scoped to **Sending access only** (cannot manage Contacts -- see below)

### `api/playtest-signup.ts`

Handles the Everlen playtest sessions signup form.

- Also validates a Turnstile token server-side
- Adds the submitter to Resend's global Contacts list via `resend.contacts.create()`
- Re-submitting the same email does **not** create a duplicate or error -- Resend's Contacts model treats email as a global unique identifier and silently updates the existing contact
- Uses a **separate** API key, `RESEND_CONTACTS_API_KEY`, because the Sending-access key used by `contact.ts` does not have permission to manage Contacts

### Environment Variables

| Variable | Used by | Notes |
|---|---|---|
| `RESEND_API_KEY` | `contact.ts` | Sending access only |
| `RESEND_CONTACTS_API_KEY` | `playtest-signup.ts` | Needs Contacts permission (Full Access) |
| `TURNSTILE_SECRET_KEY` | Both | Shared secret for server-side Turnstile validation |

All three are marked **Sensitive** in Vercel, which means Vercel blocks adding them to the **Development** environment entirely (they're only available in Production and Preview). For local testing, copy the real values into a local `.env` or `.env.local` (both are gitignored) -- `vercel pull` will **not** fetch them automatically for this reason.

The Turnstile site key (public, safe to expose) is hardcoded directly in each form component, not stored as an env var.

## Deployment

Two separate deploy targets, two separate flows:

### Frontend (Hostgator)

1. `bun run build` -> generates `dist/`
2. `bun run preview` -> verify locally before uploading
3. Zip the **contents** of `dist/` (not the folder itself)
4. Upload to `public_html/` via cPanel File Manager, extract, delete the zip
5. `.htaccess` is already configured on the server (handles SPA routing) -- it is not generated by `vite build` and does not need to be re-uploaded

### API functions (Vercel)

The Vercel project is linked to this repository and deploys automatically from `main`. Pushing to `main` triggers a new deployment -- check the **Deployments** tab to confirm it picked up the right commit before considering a feature fully live. Vercel does **not** serve the public site, only `/api/*`.

## Notes

- This project was originally scaffolded by [Lovable](https://lovable.dev/) and has since been fully decoupled -- no Lovable dependencies remain.
- `src/routeTree.gen.ts` is auto-generated by TanStack Router. Never edit it manually -- it's overwritten whenever the dev server runs.
- Videos in `public/videos/` are intentionally excluded from the Vite asset pipeline and referenced as static `/videos/...` paths, avoiding unnecessary processing of large binary files.
- Founder loop videos were converted from GIF to `.webm` for load performance (previously 16-23MB each as GIFs in `src/assets`).
- `@react-email/ui` remains listed as a dependency but is not actively used -- a leftover from initial Lovable scaffolding, flagged for removal in a future cleanup pass.
